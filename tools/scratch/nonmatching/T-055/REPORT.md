## func_8001CBCC finding (not applied)
D_80045C00 (0.017453292f) at image 0x362A0 is a **16-byte-padded block**. It sits between D_80045BEC (used by func_800193DC) and D_80045C10 (used by func_8001CD50). With the literal `0.017453292f` the function matches exactly. With any extern, defined, static, const or array form of D_80045C00 it stays 2 words off; -O3, -O1, -g3 and -mips1 don't help either.

Conclusion: the original file containing func_8001CBCC has its own one-float section at 0x362A0. That file probably starts at func_8001C370 (image 0xCA10, the first 16-aligned function start before CBCC) and ends before func_8001CD50 (0xD3F0, aligned).

To match it, the lead would need to split main_2FF0 into a new `c` subsegment [0xCA10, 0xD3F0) and give it `[0x362A0, .rodata, <tu>]` inside the data range. That is outside my yaml permission (rodata lines only), and the range includes T-052's func_8001C43C.
